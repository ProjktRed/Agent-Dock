0.36.0 was not published, so this release also carries all of it (listed below).

- **Task board** (new Tasks page in the sidebar). The plan's items appear in three columns: Planned,
  In progress and Finished. You can group them by phase or show one list. Drag items, or use the
  up/down and Move to top buttons (Alt+Up/Down on a focused row), to choose what runs next.
  - Assessment takes the highest Planned item it can do now, and only skips one that is deferred,
    already running, would touch the same files as a running task, or does not fit the task size.
  - The order is saved in Agent Dock's own state, so IMPLEMENTATION_PLAN.md is never rewritten. Reset
    to plan order puts it back.
  - In progress shows which task or parallel lane is working on each item.
- **Parallel tasks in Unattended mode.** All tasks in a round share one budget. When the run or daily
  cap is reached, every task stops at its next safe point. Each token is counted once. The engine CLI
  also has `--max-rounds`.
- **Live view of a parallel round.** Overview › Progress lists each task in the round with its stage,
  attempt and start time. The cycle highlights the stages tasks are in, and the plan card marks the
  items being worked on. Task history now also lists parallel tasks that failed or did not merge.
- **The combined check runs like QA**, with the same safety check on the command and the same
  environment.
- **GitHub CI in the app** (Projects › Workflow › GitHub CI). After Open pull request, the pushed
  commit's GitHub Actions runs show there, and you get a notification when they pass or fail. It uses
  your own GitHub CLI sign-in (`gh auth login`); the app stores no GitHub token.
  - **Fix CI failure** starts a run that fixes it from the failed log. Checks and tests are never
    weakened to make them pass.
  - **Fix failures automatically** (off by default) does that by itself and pushes the fix to the same
    branch, at most 3 times per push of yours.
- **Parallel tasks share the Elevation limit.** It is split between a round's tasks instead of applying
  to each one, and a combined check that hangs is ended after 30 minutes.
- **Diagnostics** now include the Task board order and the parallel round.
- **Claude Code installed through npm** now starts correctly on Windows.
- **Fix:** the Task history table fits its card.
- **Fix:** settings imports no longer bring in environment variables for CLI connections.
- **Fix:** Help links open the GitHub page when no app can open the bundled guide.
- **Fix:** a plan item that Assessment copies with a phase label is still checked off.

## From 0.36.0

- **Interface styles.** Settings › General › Appearance has a Style choice with previews: Neumorphic
  (the current look), Standard (flat dark panels, thin borders) and Cyberpunk (neon on near-black, angled
  edges). Dark and Darker apply to every style, and each style remembers its own accent color. Fonts are
  bundled with the app, so nothing is downloaded.
- **Consistent UI.** One style each for selected items, segmented controls, toggles and buttons across
  every page. Dates and numbers are always shown in English. Plurals are correct, empty sections say so,
  and a finished run shows a summary instead of empty task details.
- **Security hardening.** Tools are looked up only on PATH. Notification settings stay inside the engine.
  Imported settings never set program locations or turn off the tool guard. Claude Code reads only your
  own user settings. Agent config folders (`.claude/`, `.codex/`, `.opencode/`, `.husky/`,
  `.github/workflows/`, `.vscode/` and others) are protected by default. Arguments passed through
  cmd.exe are escaped. Developer tools and the default menu are off in installed builds. Details are in
  docs/security.md.
- **Parallel tasks, more reliable.**
  - A round that stops for you, or is blocked, now shows in Activity and sends its notification.
  - A usage-limit wait clears as soon as no task is waiting.
  - Only the main run sends notifications and Supervisor alerts, so nothing arrives twice.
  - A merge that a pre-commit hook refuses no longer leaves your branch dirty.
  - Files that change while the combined check runs are never restored or deleted. The round stops and
    lists them.
  - Task engines left running by a crash are stopped before the next round, and their usage is counted
    once.
  - Each merged task shows its attempt count, and the Tokens tab shows usage per role for parallel tasks.
- **Scheduled runs while closed.** Tasks now start on battery, run as soon as possible after a missed
  start, and can wake the PC (new Wake to run option). Missed or failed scheduled starts go to your
  notification channels. A 23:50 schedule checked just after midnight counts as on time.
- **Smaller updates work in the installed app.** The update assembly reads the app archive as a file.
- **User guide offline.** Settings › Help opens the bundled user guide and How it works.
- **Fix:** an Assessment answer missing its "Task skill:" line is sent back once with the reason,
  instead of blocking the run.
- **Fix:** settings and project files retry a locked rename for up to 5 seconds, like the engine.
