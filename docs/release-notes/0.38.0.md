- **Parallel tasks on local model servers.** Cline or OpenCode on llama.cpp or Ollama can now run tasks side
  by side: as many as the server answers at once (llama.cpp's slots, from llama-server --parallel N, or the
  new Requests at once setting on the Ollama connection). Task engines never start the server themselves.
  Designed with kadono, who approved the change in the local-server code.
- **Merge lane** (Projects › Workflow › Parallel lanes). Merge brings a lane's branch into the branch
  the project has checked out as one merge commit. Both folders must be clean. If the lane conflicts,
  nothing is merged and the conflicting files are listed.
- **GitLab in pull-request mode.** On gitlab.com, or a host with "gitlab" in its name, Open pull
  request opens a merge request: the push itself asks GitLab for it, so no GitLab CLI is needed. A
  server that doesn't support that gets a plain push and GitLab's new merge request page.
- **Better estimates.** Recent runs count more, and with enough history Overview shows a range
  instead of one figure. Each start records its estimate. Once a few runs can be compared with what
  they actually took, later estimates are corrected by that difference (time and tokens, at most
  ×2 either way), and the tooltip says by how much.
- **Linux: scheduled runs while Agent Dock is closed.** The AppImage gets the "Also when closed" option.
  It adds a systemd user timer per project: no root, it runs while you're signed in, and a start missed
  while the PC was off runs at your next sign-in.
- **Linux: smaller updates.** The update is a binary patch of the AppImage you have. It's installed only
  if the result matches the signed release; otherwise the whole AppImage downloads as before.
- **WSL: Stop now ends everything.** For a project running in WSL, Stop now also ends the engine and the
  agent CLIs inside the distro. Before, only the Windows side was stopped.
- **CLI settings in the app** (CLIs › Settings). Codex and Claude Code get run settings for their
  Assessment, QA, Resolver and Elevation runs (reasoning summary, verbosity, fallback model, token
  budgets, command timeouts and more; nothing that loosens the sandbox or permissions) and an editor for
  their own config file, checked before saving and backed up. Ollama's server settings (requests at
  once, context length, KV cache, flash attention, keep-alive, models folder) can be changed on Windows,
  and each shows what the running Ollama actually uses.
- **Security:** the window now loads from a private app:// address instead of local files, so local-file
  pages no longer need extra privileges (Electron's GrantFileProtocolExtraPrivileges fuse is off).
- **Fixes:** a run that stopped before choosing its first task (for example Assessment failing) no longer
  marks the previous run's last task as blocked in Projects › History. The cost in Overview's estimate
  shows its $ sign again.
