# Agent Dock 0.40.0 (draft)

## Fixes
- **Allow now reaches commands it should.** An agent's inline script (for example `node -e` that writes an icon file) was refused outright because pieces of code in it looked like protected file names, so you were never asked and the task ended blocked. Such commands are now put to you as an Ask, with the full command shown. Commands that really name a protected path are still refused without asking.

## Safety
- **Checks wait for a clean scope.** When the work already fails the scope check (changes outside the task's paths, or to protected ones), the project's check command is not run. The task stops on the scope problem, as before.
- **Approvals are tied to what you saw.** After you allow an action, the guard checks it again against the current policy. A policy that changed while you were deciding, or an action that now points at a protected path, is refused. "Allow for this run" covers only the same call in the same task and run, and Agent Dock keeps only fingerprints of it and a short preview with credentials removed. Command text in Ask requests has credentials removed too.
- **Size limit on hook input.** Codex and Claude Code tool calls larger than 2 MB are refused.
- **Checks can't use your sign-ins.** On top of the credentials removed in 0.39.2, check commands no longer get your SSH agent, git/ssh password helpers, a custom SSH command, or npm's user config and client certificate. Checks don't install anything and need no sign-in. Agents keep these for now.
- **Claude's sandbox keeps commands out of your secrets.** With "Run agents' commands in a sandbox" on, Claude Code's commands can't read your sign-ins (SSH, cloud, npm, git and CLI credentials in your home folder) or the protected paths, and can't write the protected paths. This needs Claude Code 2.1.221 or later; an older CLI refuses the run with a message instead of running with weaker limits. Claude Code's sandbox doesn't run on native Windows. There, every sandboxed Claude run (implementation, roles and QA) now refuses with a clear reason (use WSL2) instead of exiting at startup.
- **Git that Agent Dock runs for you doesn't run the repository's programs.** Every git command Agent Dock runs turns off fsmonitor programs, git hooks, external diff and textconv programs, and file:// submodule fetches. A run refuses to start in a repository whose own config names a program git would start otherwise: a credential helper, an SSH command, a filter (Git LFS is fine), a merge driver, a GPG program or repository-enabled commit signing, upload/receive-pack, or an include. The message names the setting to remove. A run also refuses when the project's `.git` points somewhere that isn't a worktree its repository registered. Your global git settings are untouched, so pushing and LFS work as before.
  - **Changed behavior:** your repository's git hooks (husky and others) no longer run for commits Agent Dock makes itself, such as parallel merges and the plan commit. Pushes keep them, so Git LFS still uploads its files. Your own commits are unaffected.
- **Clearer refusal for MCP and unknown tools.** Codex and Claude Code calls to a tool the guard doesn't know, MCP tools included, are refused whatever the tool-guard setting, as before. The reason now names the tool instead of only saying "Protected-path policy refused".

## Fixes from kadono's 0.39.3 report
- A Codex provider whose `env_key` names a system variable (PATH, HOME, TEMP and the like) no longer strips that variable from every process. The key isn't passed through.
- A Codex config with the same key twice no longer guesses between them. Neither is used.
