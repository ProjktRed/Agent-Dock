- **Fix: the app froze on a project with many uncommitted files.** With an untracked `node_modules`
  (thousands of files), a blocked task's scope message listed every file, and the app re-read that
  text, the whole changed-file list and the blocked case (about 14 seconds of work on a 10,000-file
  tree) on every status refresh. The scope message now names the first 20 files and counts the rest;
  long texts in activity and status are shortened; the window gets the first 1,000 changed files and
  the total; the blocked-case check runs again only when its inputs change and takes a fraction of the
  time. State written by earlier versions is shortened when it is read. Tip: add `node_modules/` to the
  project's `.gitignore`.
- **Fix: Codex with a custom model provider gets its key again.** Since 0.39.2, Codex runs kept only
  `OPENAI_API_KEY` and `CODEX_API_KEY`, so a provider whose `config.toml` reads its key from another
  variable (for example `env_key = "AZURE_OPENAI_API_KEY"`) failed to sign in. Codex now also keeps the
  variable the active provider names, and only that one, and treats it as a secret. Define the
  provider as a `[model_providers.<id>]` table with plain strings: if the reader finds
  provider or profile settings it can't read (inline tables, escaped strings), only the two default
  variables are kept.
- **Note on checks:** since 0.39.2, check commands also lose credential files and registry tokens
  (`GOOGLE_APPLICATION_CREDENTIALS`, `AWS_SHARED_CREDENTIALS_FILE`, `NPM_TOKEN`, `NODE_AUTH_TOKEN`,
  `COMPOSER_AUTH`), not only `GITHUB_TOKEN`. A check that installs from a private registry or calls a
  cloud service fails; install dependencies before the run. Thanks to kadono.
