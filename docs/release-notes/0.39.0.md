- **Security: tighter protection around agents.** Several ways an agent's commands could reach
  protected files are closed, on every CLI. Read commands keep working with their usual options
  (PowerShell's `Get-Content -Raw` and the like are no longer refused, which blocked Codex Assessment on
  Windows in 0.38.1). Thanks to kadono and to the reviews that found them.
- **Project checks are untrusted by default** (Settings › Execution & safety › Project checks). Agents
  can edit the code a check such as `npm test` runs. While a run is going, Agent Dock now puts back any
  change something else makes to its own settings files and stops every run when those or its engine
  files change. Packaged builds also check the engine's files against a list signed into the app
  before they use them. Turn it on only for projects whose tests you trust completely.
- **Safety changes ask first.** Turning off the tool guard (also for a single project) or the engine
  guardrails, trusting checks, unprotecting a path, accepting remote approvals, changing a program Agent
  Dock runs (including a CLI program not found on PATH) or where updates come from, and sending a saved
  API key to a connection's new address all ask you to confirm. A malformed save no longer resets your
  settings.
- **Signed action log.** Each project's action log is now signed with a key the app keeps encrypted, and
  Settings › Verify logs shows how many entries are signed. `docs/security.md` explains what the
  signature does and does not cover.
- **Upgrading:** connection API keys are stored in a new way. If you go back to 0.38.x, enter them again
  in CLIs.
- **Email approvals** can only Stop a run or Dismiss a plan change, within an hour. Everything else is
  answered in the app or with the Telegram buttons.
- **Fixes:**
  - Parallel tasks with a Codex or Claude Code implementer really run side by side (they ran one at a
    time).
  - The OpenCode reasoning variant no longer makes every OpenCode run fail.
  - A project stopped with Stop now while another project was open no longer shows "running" forever.
  - Claude Code workers use the config folder the settings editor uses (`CLAUDE_CONFIG_DIR`).
  - A run that finishes within seconds is no longer reported as a startup failure.
  - Unattended runs retry a usage limit by themselves in Assessment, QA, Resolver and Elevation too.
  - Codex calls and checks that never finish are ended (after 2 hours and 1 hour), and their output is
    capped.
  - Parallel worktrees are created one at a time; engine git reads never hold the index lock.
  - The dashboard copes with a half-written log line and with no run state yet.
  - Role names keep their quotes; a project name cannot leave the chosen folder; a file cannot be added
    as a project; settings imports with malformed values are applied safely.
  - Many projects no longer start hundreds of git processes at once.
- **Privacy:** the diagnostics export leaves out task prompts and objectives, secret connection
  variables are stored encrypted, config files keep private permissions, and Linux no longer downloads
  spellcheck dictionaries.
