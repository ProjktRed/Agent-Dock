- **Security: tighter protection around agents.** Several ways an agent's commands could reach
  protected files are closed, on every CLI. Read commands keep working with their usual options
  (PowerShell's `Get-Content -Raw` and the like are no longer refused, which blocked Codex Assessment on
  Windows in 0.38.1). Thanks to kadono and to the reviews that found them.
- **Project checks are untrusted by default** (Settings › Execution & safety › Project checks). Agents
  can edit the code a check such as `npm test` runs. While a run is going, Agent Dock now puts back any
  change something else makes to its own settings files and stops every run when those or its engine
  files change. Packaged builds also check the engine's files against a list signed into the app
  before they use them. Turn it on only for projects whose tests you trust completely.
- **Safety level** (Settings › Execution & safety): Strict, Standard or Trusted sets the safety toggles in
  one choice. New with it:
  - **Ask instead of refuse.** When Codex or Claude Code tries something the guard cannot verify (a web tool,
    a shell command it cannot read), Agent Dock asks you in its window, or on Telegram, instead of stopping the
    task: Refuse, Allow once, or Allow for this run (that exact command stops asking until the run ends). No
    answer in time means refused. Anything touching protected files is still refused outright.
  - **Missing tools.** When a task's check needs a toolchain that is not installed (Rust, Go, Python, .NET, Java,
    Deno, Bun and others), the task waits before any agent runs, and Overview suggests installing it: Install
    opens a terminal with the official command after you confirm, or open the download page. The task continues
    by itself once the tool is found, or you set it aside.
  - **Web access for agents** (on in Standard and Trusted, off in Strict). Codex's live web search and Claude
    Code's web search and page reading, for Implementation and Assessment; QA never gets them. Off also turns
    off Codex's own default cached search.
  - **Fewer questions.** The guard now reads a few more everyday commands as safe on its own: reading several
    files in one PowerShell command, listing which files changed (also staged ones), and asking a tool for its
    version or location.
  - **Approve each task.** Each task Assessment picks waits for your Approve or Set aside before any code is
    written.
- **Experimental: sandboxed checks** (Settings › Execution & safety › Experimental, off by default).
  Project checks run inside Anthropic's sandbox runtime: no network, writes only inside the project, and
  Agent Dock's saved keys and CLI sign-ins out of reach. On Windows checks run as a separate local account
  that Agent Dock sets up when you turn this on (one administrator prompt) and that cannot open your
  profile; files outside it that every account may read, on another drive for example, stay readable, so a
  portable copy's data folder fails the self-test. On Linux it uses bubblewrap, which hides your home folder.
  It turns on only after a self-test passes, and a check that cannot start in the sandbox fails instead of
  running outside it.
- **Experimental: sandboxed agent commands** (same place). The shell commands Codex and Claude Code run get
  the same limits: no network, writes only inside the project. Claude Code uses the sandbox runtime; Codex on
  Windows uses its own elevated sandbox, which must already be set up.
- **Stash and pop on Overview.** The new Workspace card shows the project's uncommitted changes and its git
  stashes. **Stash changes** puts every uncommitted change (untracked files too) in a named stash, so a run
  that needs a clean workspace can start; **Pop** puts a stash's work back into a clean workspace; **Delete**
  (asks twice) drops one. Set-aside tasks' stashes are listed there too. All only while the project is
  stopped. The card and the Blocked/Attention panel start collapsed to one line; Show details opens them, and
  Resolve attention in the title bar opens the panel.
- **Choose the next task.** Tasks › **Do next** (the play button on a planned item) puts it first in the
  whole priority order, across phases, and removes its deferred mark. The ✕ on a Deferred badge removes the
  mark alone. The new **Set aside** list shows every set-aside task, also those with no plan item, with
  **Remove mark** and **Run next** (the task, unchanged, becomes the first task of the next start).
- **Project skill** (Projects › Project skill). A read-only agent (Codex, Claude Code or a local model)
  drafts a SKILL.md from the workspace: its layout, the exact build and test commands, the conventions its
  code follows and its pitfalls. You review and edit it; Save keeps it in Agent Dock's state folder, not
  in the repository, and every role of that project gets it from the next start.
- **Cline and OpenCode never see your provider key.** On a cloud provider (OpenRouter, OpenCode Console,
  OpenAI-compatible) they now talk to a small key broker inside the engine with a token made for the run;
  the engine adds the key on the way to the provider. A key limit at the provider is still recommended.
- **Safety changes ask first.** Turning off the tool guard (also for a single project) or the engine
  guardrails, trusting checks, unprotecting a path, accepting remote approvals, changing a program Agent
  Dock runs (including a CLI program not found on PATH) or where updates come from, and sending a saved
  API key to a connection's new address all ask you to confirm. A malformed save no longer resets your
  settings.
- **Signed action log.** Each project's action log is now signed with a key the app keeps encrypted, and
  Settings › Verify logs shows how many entries are signed. `docs/security.md` explains what the
  signature does and does not cover.
- **Upgrading:** connection API keys are stored in a new way. If you go back to 0.38.x, enter them again
  in CLIs.
- **Email approvals** can only Stop a run or Dismiss a plan change, within an hour. Everything else is
  answered in the app or with the Telegram buttons.
- **Fixes:**
  - Parallel tasks with a Codex or Claude Code implementer really run side by side (they ran one at a
    time).
  - The OpenCode reasoning variant no longer makes every OpenCode run fail.
  - A project stopped with Stop now while another project was open no longer shows "running" forever.
  - Claude Code workers use the config folder the settings editor uses (`CLAUDE_CONFIG_DIR`).
  - A run that finishes within seconds is no longer reported as a startup failure.
  - Unattended runs retry a usage limit by themselves in Assessment, QA, Resolver and Elevation too.
  - Codex calls and checks that never finish are ended (after 2 hours and 1 hour), and their output is
    capped.
  - Parallel worktrees are created one at a time; engine git reads never hold the index lock.
  - The dashboard copes with a half-written log line and with no run state yet.
  - Role names keep their quotes; a project name cannot leave the chosen folder; a file cannot be added
    as a project; settings imports with malformed values are applied safely.
  - Many projects no longer start hundreds of git processes at once.
  - Run again no longer loses its task when the start stops first (for example on uncommitted changes):
    the task stays attached until the engine takes it on, and that first stop is listed under it.
  - A task waiting for your Approve when the run was stopped asks again after the restart; it used to wait
    without showing the card, with the project shown as stopped.
  - The Windows sandbox self-test runs: its probe no longer sits in a folder the sandbox account cannot
    open.
- **Privacy:** the diagnostics export leaves out task prompts and objectives, secret connection
  variables are stored encrypted, config files keep private permissions, and Linux no longer downloads
  spellcheck dictionaries.

## Simpler

- **Loop limits and Eco sizing are no longer settings.** Elevation after, Correction limit, Resolver strategies
  and Eco's files-per-task, new file size and files-to-read used the engine's values unless guardrails were off.
  They are now always the engine's; the task size (Eco, Standard, Max) is the choice that matters, and Max keeps
  its own limits. Values saved by earlier versions are dropped.
- **No more browser dashboard in the engine.** The engine's separate web server and browser page (for running
  the engine without the app) are gone; Agent Dock was already the dashboard. Run the engine on its own with
  `node src/cli.mjs`; it opens no network port.
- **One way to run work in parallel: Parallel tasks.** Parallel lanes (a worktree per objective, merged by
  hand) are gone. Lanes you already made stay as ordinary projects in their folders, on their
  `agent-dock/lane-…` branches; merge those with git or a pull request.
- **The Supervisor is its fixed monitors again.** Stall, repeated failure, guard refusals, burn rate, scope creep
  and plan drift still alert, pause or stop as you set them, and the digest stays. The model review on alerts
  (and its proposals, deferring and cap changes) and the suggested plan changes are gone; plan items are still
  checked off when QA approves the task that completes them.
- **Workflow: one Second review before QA.** Custom roles at three stages, advisory roles, templates and
  self-fixing reviews are replaced by one optional reviewer on its own agent that can send an attempt
  back. Roles you made earlier are no longer run (their folders are kept); the second-opinion QA carries
  over as the Second review.
- **No automatic step-down.** A Standard or Max task that fails review is no longer set aside and redone
  one size smaller; the task size you choose stays for the whole run. Tasks an earlier version set
  aside this way are listed with the other deferred tasks.
- **Agent Dock no longer edits other programs' settings.** CLIs › Settings shows where Codex's and Claude
  Code's own config files are (**Show config file**) instead of editing them, and shows Ollama's server
  settings without changing your environment. Run settings are unchanged.
- **No automatic CI repair.** Fix CI failure and the automatic fix loop are gone. Projects › Workflow ›
  GitHub CI still shows the pushed commit's runs, links each one on GitHub and tells you when they finish.
- **Scheduled runs only while Agent Dock is open.** Also when closed and Wake to run are gone; Agent Dock
  no longer adds Windows Task Scheduler tasks or systemd user timers. On the first launch it removes the
  ones earlier versions made (another install's are left alone).
