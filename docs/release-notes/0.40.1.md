- **Fix: with "sandbox agents' commands" on, a Codex run whose sandbox can't be confirmed is refused.** 0.40.0
  fell back to Codex's plain sandbox when its permissions profile could not start at all (an older Codex, or a
  bubblewrap build that can't hide more than one sign-in file such as `~/.npmrc` and `~/.netrc`), even with the
  setting on. It now refuses the run, as the setting promises. With the setting off, Agent Dock tries the profile
  again without the single-file rules: the folders (`~/.ssh`, `~/.aws`, Codex's home, Agent Dock's data) stay
  hidden, and the run's attestation names the files that stay readable.
- **Fix: Codex can no longer type commands into a shell past the guard.** Codex can send input to a command that
  is still running, and its hooks never see that input. The guard now refuses commands that start a shell or
  interpreter waiting for input (`bash` on its own, `powershell` without `-Command`, `python` or `node` without a
  script, `xargs`), outright and without asking. Scripts run as before: `bash -c "…"`, `node build.js`,
  `powershell -Command …`.
- **Fix: wildcards that could name a protected file are refused outright.** With "Ask" on, `cat .e*` or
  `cat .[e]nv` was put to you, and a yes read `.env`. Wildcards that match a protected file, or fit a protected
  name, are now refused without a question.
- **Fix: Claude's commands don't get its key.** Claude Code runs with its subprocess scrub on, so the commands it
  runs (and its hooks) no longer inherit `ANTHROPIC_API_KEY` or cloud credentials. Claude itself still signs in.
- **Fix: no empty `/tmp/.git` after Codex runs on Linux.** Codex's profile sandbox left empty `.git`, `.codex` and
  `.agents` folders in the temp folder; Agent Dock removes them after each run while they are empty.
- Smaller fixes: the action log's attestation says whether decisions are signed; the web-fetch check also
  recognizes private addresses written inside IPv6 (NAT64, 6to4, IPv4-compatible and hex-mapped forms); the tool
  list behind the decision log's type field knows Claude Code's and Codex's current tool names. Thanks to kadono.
